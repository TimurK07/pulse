# PULSE: дизайн-исследование и дизайн-система

Документ для реализации UI платформы обратной связи сотрудников ГК «Модус Трейд». Язык интерфейса — русский. Ориентир по качеству — B2B SaaS уровня Linear, Vercel, Raycast. Ни одного из них мы не копируем: заимствуем принципы, а не внешний вид.

Дата исследования: 10.11.2026. Все URL ниже я открыл сам через WebFetch или нашёл в результатах WebSearch. Если источник известен только по сниппету поиска, это отмечено.

## 1. Референсы (14)

### R1. Linear: редизайн UI (2024) и «спокойный» рефреш (2026)
- https://linear.app/now/how-we-redesigned-the-linear-ui
- https://linear.app/now/behind-the-latest-design-refresh
- https://linear.app/changelog/2026-03-12-ui-refresh
- **Что это.** Два эссе команды Linear о перестройке интерфейса и запись в changelog.
- **Что прочитано.** Темы генерируются в LCH из трёх переменных (base, accent, contrast) вместо 98. Есть отдельная переменная контраста для high-contrast тем. Уровни поверхностей: фон, панели, диалоги, модалки. Глобальный хром — «inverted L-shape». В 2026 году сайдбар стал «на несколько ступеней тусклее», чтобы доминировала рабочая область. Палитру увели от холодной синеватой к «более тёплому серому», с оговоркой, что слишком тёплый выглядит «грязным». Иконок стало меньше, разделителей тоже («fewer separators»).
- **Что берём.**
  - Навигация: приглушённый сайдбар, контент ярче хрома.
  - Цветовая система: тема из нескольких опорных токенов, а не из сотни ручных.
  - Плотность: убираем лишние разделители и иконки.
  - Тёплый нейтральный цвет: это **подтверждает** выбранное направление «бумаги», но с ограничением по насыщенности.
- **Чего избегаем.** Фиолетового акцента и Inter. Не делаем «Linear-клон» с иконками статусов-кругов в том же стиле: наши иконки статусов рисуем сами (см. §3.10).

### R2. Linear: Triage
- https://linear.app/docs/triage
- **Что это.** Документация входящей очереди.
- **Что прочитано.** Действия над входящей задачей: Accept (с опциональным комментарием), Decline (статус Canceled плюс комментарий-объяснение), Mark as duplicate, Snooze, «Comment and keep in Triage», то есть запрос информации без выхода из очереди. Горячие клавиши: `1` — принять, `2` — отклонить, `3` — дубликат, `H` — отложить. Есть ротация дежурного по триажу.
- **Что берём.** Корпоративные паттерны:
  - Очередь руководителя как отдельный «инбокс» с фиксированным набором решений.
  - **Отклонение всегда с обоснованием** (у нас поле обязательное).
  - «Запросить уточнение» как действие, которое оставляет обращение в очереди.
  - Цифровые клавиши для решений.
- **Чего избегаем.** Скрытой механики snooze: в корпоративной системе обратной связи «отложенное» обращение не должно исчезать с глаз без следа.

### R3. Linear: Triage Intelligence (ИИ-подсказки)
- https://linear.app/docs/triage-intelligence
- Сниппет поиска: https://linear.app/changelog/2025-08-14-product-intelligence-technology-preview
- **Что прочитано.** Панель подсказок находится **под заголовком задачи**. Подсказываются свойства (команда, исполнитель, метки) и возможные дубликаты. Подсказку можно принять или отклонить. По наведению видно, *почему* она появилась. По сниппету changelog, автоприменённые свойства явно помечены в заголовке блока подсказок.
- **Что берём.** Детальная страница:
  - Место ИИ-блока — сразу под заголовком, до описания.
  - Каждая подсказка поддерживает «принять / отклонить / почему».
  - Автоприменённое помечается отдельно.
- **Чего избегаем.** Подсказок без указания источника. У нас обязательно различие «ИИ» и «правило» (см. §3.13).

### R4. Linear: SLA (только сниппет поиска)
- https://linear.app/docs/sla (WebFetch отдаёт 404, данные из сниппета WebSearch)
- **Что прочитано.** SLA показывается иконкой-пламенем, цвет которой переходит серый → жёлтый → оранжевый → красный по мере приближения дедлайна. Уровни риска: Low — больше недели, Medium — меньше недели, High — меньше суток, Breached — просрочено. Есть фильтр по SLA-статусу. Уведомления приходят за 24 часа и при нарушении.
- **Что берём.** Отображение SLA:
  - Градация риска по порогам, а не только «просрочено / нет».
  - Фильтр очереди по SLA.
  - Уведомление за 24 часа.
- **Чего избегаем.** Оранжевой ступени: у нас оранжевый — бренд-акцент, и он не участвует в шкале риска. Шкала у нас трёхступенчатая: нейтрально → янтарь → красный. Иконка — часы, а не огонь. Огонь — эмоциональный образ, для обращений сотрудников неуместен.

### R5. Vercel Geist: цвета
- https://vercel.com/geist/colors
- **Что прочитано.** 10 шкал по 10 ступеней с жёсткой семантикой ступеней:
  - 100–300 — фоны (default, hover, active);
  - 400–600 — границы (default, hover, active);
  - 700–800 — заливки высокого контраста;
  - 900–1000 — вторичный и основной текст.
  
  Фонов всего два: Background 1 используется почти везде, Background 2 — «редко». Граница по умолчанию — сплошная gray-400. Совет «рисовать каждую границу один раз».
- **Что берём.** Цветовая система:
  - Токены называются **по роли** (bg / border / text), а не по цвету.
  - У интерактивных элементов хватает трёх состояний фона.
  - Одна граница на ребро, без двойных линий.
- **Чего избегаем.** Не копируем гамму Geist: она холодная, «чёрно-белая Vercel».

### R6. Vercel: Web Interface Guidelines и редизайн дашборда
- https://vercel.com/design/guidelines
- https://vercel.com/blog/dashboard-redesign
- **Что прочитано.**
  - Анимировать только `transform`/`opacity`, «Never `transition: all`», обязательна reduced-motion версия, анимация должна прерываться.
  - `tabular-nums` или моноширинный шрифт для сравниваемых чисел.
  - «All states designed. Empty, sparse, dense, & error states.»
  - «No dead ends».
  - Не полагаться только на цвет.
  - Видимый focus-ring на всём, `:focus-visible`.
  - Не дизейблить submit заранее; ошибки показывать рядом с полем.
  - Дашборд Vercel начинается со **статуса продакшена и последнего деплоя**, а статус деплоя виден в favicon и заголовке вкладки.
- **Что берём.**
  - Формы и интерактивные состояния — как в гайдлайнах.
  - Главный экран начинается со статуса и того, что требует действия, а не со сводки.
  - Счётчик просроченных обращений выводим в `<title>` вкладки, например «(3) Очередь — PULSE».
- **Чего избегаем.** Скриншотов-превью вместо данных.

### R7. Radix Colors: семантика 12-ступенчатой шкалы
- https://www.radix-ui.com/colors/docs/palette-composition/understanding-the-scale
- **Что прочитано.** 1–2 — фон приложения; 3–5 — фон компонента (норма, hover, pressed); 6–8 — границы (неинтерактивные, интерактивные, фокус); 9–10 — сплошная заливка и её hover; 11–12 — текст низкого и высокого контраста. Ступени 11 и 12 рассчитаны на APCA Lc 60 и Lc 90 на фоне ступени 2. У жёлтого и янтарного на ступени 9 — **тёмный текст**.
- **Что берём.**
  - Каждому статусу даём тройку `tint` (фон), `fg` (текст и иконка), `border`.
  - Прецедент «тёмный текст на тёплой яркой заливке» обосновывает чёрный текст на сигнальном оранжевом.

### R8. IBM Carbon: моушн и индикаторы статуса
- https://carbondesignsystem.com/elements/motion/overview/
- https://carbondesignsystem.com/patterns/status-indicator-pattern/
- **Что прочитано.**
  - Моушн бывает productive (для задач: незаметный, быстрый) и expressive (для значимых моментов).
  - Длительности: 70 / 110 / 150 / 240 / 400 / 700 мс.
  - Кривые: standard `cubic-bezier(0.2,0,0.38,0.9)`, entrance `(0,0,0.38,0.9)`, exit `(0.2,0,1,0.9)`.
  - Статус передаётся минимум двумя каналами из трёх: цвет, форма, символ.
  - Семантика цвета: красный — ошибка, **оранжевый — серьёзное предупреждение**, жёлтый — предупреждение, зелёный — успех, синий — прогресс процесса, серый — не начато, фиолетовый — выброс или неопределённое.
  - Контраст индикатора с фоном не меньше 3:1. Не больше 5–6 индикаторов на экран.
- **Что берём.** Моушн, статус-пиллы и SLA:
  - Шкала длительностей и кривые productive (§3.9).
  - Статус = иконка-форма + цвет + текст.
- **Что настораживает.** В конвенции Carbon оранжевый означает «серьёзное предупреждение». Это аргумент **против** использования акцента в статусах: см. проверку направления (§2).

### R9. GitHub Issues: история редизайна и компонент Timeline (Primer)
- https://markdotto.com/blog/shipping-the-new-github-issues/
- https://primer.style/product/components/timeline/
- **Что прочитано (Mark Otto).**
  - Цель «одна строка на задачу» он сам назвал «a bit of a crazy goal». В итоге сделали более табличную раскладку.
  - Метки-точки вернули к полным текстовым меткам.
  - Вернули цвета open/closed на иконки.
  - Убрали серый фон списка, потому что он давал «полосатость».
  - Фильтры стали лёгкими текстовыми «кнопками» над списком вместо тяжёлого ряда кнопок.
  - Поиск убрали из главной роли.
- **Что прочитано (Primer Timeline).** Элемент состоит из Badge (иконка с вариантом статуса), Body и Break. Вариант `condensed` уменьшает отступы и убирает фон бейджа.
- **Что берём.** Плотность и детальная страница:
  - Строка очереди однострочная, но **с текстовыми метками**, а не с цветными точками без подписи.
  - Фильтры оформлены как тихие текстовые контролы.
  - Таймлайн разделяет два веса: *condensed*-события (смена статуса, назначение) и полноформатные комментарии.
- **Чего избегаем.** Поиска как главного входа и боковой колонки с табами (GitHub это пробовал и отказался).

### R10. Canny: статусы постов и уведомление проголосовавших
- https://help.canny.io/en/articles/673583-post-statuses
- **Что прочитано.** Статусы: Open, Under Review («we are considering this»), Planned, In Progress, Complete, Closed («we will not work on this»). Статус меняется в **правой панели** поста, к смене можно приложить комментарий. Этот комментарий уходит проголосовавшим в email.
- **Что берём.**
  - Смена статуса — это событие с текстом-обоснованием, которое видит автор обращения.
  - Для «Отклонено» текст обязателен, для остальных статусов — по желанию.
  - У каждого статуса есть короткое пояснение на человеческом языке. Мы показываем его в тултипе пилла, например: «Отклонено — решение принято, причина указана в истории».
- **Чего избегаем.** Публичных голосований как основной механики: это внутренний инструмент, а не публичный роадмап.

### R11. Workleap Officevibe: раздел Feedback
- https://help.workleap.com/en/articles/10281709-feedback-section-overview
- https://help.workleap.com/en/articles/10281702-team-feedback-how-it-works (сниппет поиска)
- **Что прочитано.**
  - Анонимная обратная связь показывается руководителю, только если в команде не меньше 5 активных участников (сниппет).
  - Имя команды скрывается при размере меньше 5.
  - Ответы оформлены тредом-беседой.
  - Удалённое сообщение заменяется плашкой «The author requested this feedback to be deleted.» с датой.
  - Есть кнопка «Analyze feedback» с ИИ-сводкой.
- **Что берём.** Корпоративные паттерны:
  - Анонимность отображается явно, как отдельный тип автора («Анонимно», иконка маски, без аватара).
  - Есть порог раскрытия отдела в аналитике.
  - Удаление оставляет след в таймлайне.
  - ИИ-анализ вызывается явной кнопкой, а не включён всегда.

### R12. Culture Amp: heatmap результатов
- https://www.cultureamp.com/blog/heatmapping-your-engagement-results
- **Что прочитано.**
  - Группы показываются как **дельта** от общекорпоративного значения.
  - Группы упорядочены по размеру.
  - Предупреждение: маленькие группы дают большие дельты и «перетягивают взгляд».
  - Цвета только зелёный и красный.
- **Что берём.** Аналитика:
  - Повторяющиеся проблемы показываем таблицей отдел × категория со значением и дельтой к среднему.
  - Отделы с малой выборкой приглушаем и помечаем «мало данных».
  - Таблица с тонированием ячеек вместо круговых диаграмм.
- **Чего избегаем.** Красно-зелёной дихотомии: она плоха для дальтоников. У нас односторонняя тёплая шкала интенсивности и текстовое значение в каждой ячейке.

### R13. Shape of AI: каталог UX-паттернов для ИИ
- https://www.shapeof.ai/
- **Что прочитано.** Категории паттернов:
  - Trust builders: Disclosure («clearly marks content… AI guided or delivered»), Caveat, Footprints.
  - Governors: Citations, Verification («confirm AI decisions… before proceeding»).
  - Identifiers: Color, Iconography, Name.
- **Что берём.** Презентация ИИ:
  - Disclosure — метка «ИИ» на каждом сгенерированном элементе.
  - Verification — ИИ ничего не применяет без подтверждения.
  - Footprints — в таймлайне фиксируется «по подсказке ИИ, принял(а) …».
  - Caveat — при fallback честно пишем, что ИИ недоступен.
- **Чего избегаем.** Identifier через цвет. Отдельный «ИИ-цвет» мы **не вводим**, у нас уже 7 статусных хью. ИИ-блок различается формой: пунктирная рамка = «предложение, ещё не принято».

### R14. Raycast и Rauno Freiberg: клавиатура и частотность анимаций
- https://www.raycast.com/blog/a-fresh-look-and-feel
- https://rauno.me/craft/interaction-design
- **Что прочитано (Raycast).** Нижняя Action Bar показывает доступные действия **вместе с их сочетаниями клавиш**, «so users learn them over time». Единый набор иконок с одинаковой толщиной штриха и одинаковыми правилами скруглений.
- **Что прочитано (Rauno).** Действия, которые выполняются «сотни раз в день», теряют новизну. Их анимация становится когнитивной нагрузкой и делает интерфейс медленнее. Командные и контекстные меню анимировать не нужно. Анимация должна прерываться.
- **Что берём.**
  - Панель действий в карточке обращения показывает хоткеи рядом с подписью: «Принять `1`», «Уточнить `2`», «Отклонить `3`».
  - Командное меню `⌘K` / `Ctrl K` открывается **без анимации**.
  - Иконки — один набор с одной толщиной штриха (Lucide 1.5px или аналог).
- **Чего избегаем.** «Пружинящих» анимаций на частых действиях.

Дизайнеры Андрей Кудрявцев и Дмитрий Волошин, лицензия OFL, переменный шрифт с осью `wght` 100–900, подмножества cyrillic и cyrillic-ext. **Мои замеры по файлу шрифта:** UPM 1000, x-height 527, cap-height 707. GSUB содержит `tnum`, `pnum`, `case`, `ss01`, `ss02`, `salt`, `calt`.
- **Safety orange**: в результатах поиска (вторичные источники, производные от Wikipedia) для ANSI Z535 чаще всего указывают `#FF7900`, а также `#FF6600`/`#FF6700`. Первичный текст стандарта я **не видел**.

## 2. Проверка выбранного направления

| Решение | Вердикт | Обоснование и поправки |
|---|---|---|
| Тёплый «бумажный» off-white фон | **Подтверждаю с ограничением** | Linear в 2026 сам ушёл к «более тёплому серому» и прямо предупредил, что перебор тепла выглядит «грязно» (R1). Держим хрому очень низкой: фон `#F6F4EF` — едва тёплый, не кремовый и не жёлтый. Белые поверхности не используем совсем, самая светлая — `#FFFFFF` только для поповеров. |
| Почти чёрный «чернильный» текст | **Подтверждаю** | `#1C1B18` на фоне даёт 15.7:1. Чистый `#000` на тёплом фоне выглядит грязно-холодным. |
| Один акцент — сигнальный оранжевый | **Подтверждаю, но меняю способ применения** | 1) Оранжевый `#FF6B12` с белым текстом даёт **2.85:1, это провал AA**. Поэтому основная кнопка — **чёрный текст на оранжевом** (6.04:1). Это совпадает с языком промышленной маркировки и сразу отличает нас от Linear/Vercel (белый на бренде) и от «AI-дашбордов». 2) По Carbon (R8) оранжевый означает «серьёзное предупреждение». Поэтому акцент **запрещён** в статусах, SLA и приоритетах. Он означает только «здесь действие или выбор пользователя»: основная кнопка, фокус, выбранный пункт навигации, точка непрочитанного. 3) Для оранжевого текста и ссылок нужен отдельный тёмный тон `#B4480C` (4.93:1 на фоне). |
| Сдержанные статусные цвета | **Подтверждаю** | Пилл = тонированный фон + цветной текст, оба AA. Сплошных насыщенных заливок с белым текстом нет. Терминальные статусы «Отклонено» и «Закрыто» нейтральные, чтобы закрытое уходило на второй план. |
| Плотные списки в духе Linear | **Подтверждаю с поправкой GitHub** | Одна строка на обращение, но с текстовыми метками категорий (R9). Высота строки 36px: Onest мельче Inter по x-height (0.527), поэтому базовый размер 14px, а не 13px. |
| Onest + JetBrains Mono | **Подтверждаю** | Onest — родной кириллический гротеск под OFL, переменный 100–900, есть `tnum` (проверено по файлу). Mono используем только для ID, таймеров SLA, дат в таблицах и хоткеев — как «приборный» голос, отсылка к маркировке оборудования. |
| Компактный сайдбар | **Подтверждаю** | Приглушённый относительно контента (R1). Ширина 232px, свёрнутый — 52px. |
| Детальная страница: основная колонка + правая панель свойств | **Подтверждаю** | Свойства и смена статуса в правой панели — как у Canny (R10). Таймлайн с двумя весами — как у GitHub/Primer (R9). ИИ-блок под заголовком — как у Linear (R3). |
| Главная руководителя «что требует внимания» вместо 4 KPI-карточек | **Подтверждаю** | Vercel ставит первым статус, а не сводку (R6). Culture Amp ведёт к фокус-областям и плану действий (поиск, R12). 4 KPI-карточки — главный маркер «AI-дашборда» (§4). |

## 3. Дизайн-система: конкретные значения

### 3.1. Типографика

Шрифты:
```css
--font-sans: "Onest", system-ui, -apple-system, "Segoe UI", Roboto, sans-serif;
--font-mono: "JetBrains Mono", ui-monospace, "SF Mono", Menlo, monospace;
```
- Через `next/font/google` подключаем подмножества `cyrillic` и `latin`.
- Глобально задаём `font-feature-settings: "calt"`. Для чисел в таблицах, аналитике и счётчиках — `font-variant-numeric: tabular-nums`: в Onest есть `tnum`.
- Используем только веса **400, 500 и 600**. Вес 700 и выше не используем: на кириллице жирный Onest быстро «чернеет».

| Токен | px | line-height | weight | letter-spacing | Где |
|---|---|---|---|---|---|
| `display` | 28 | 36 | 600 | -0.02em | Только пустые экраны первого запуска и логин |
| `title-xl` | 22 | 30 | 600 | -0.015em | Заголовок обращения на детальной странице |
| `title-lg` | 18 | 26 | 600 | -0.01em | Заголовок страницы («Очередь», «Аналитика») |
| `title-md` | 15 | 22 | 600 | -0.005em | Заголовки секций и групп на главной |
| `body` | 14 | 22 | 400 | 0 | Описание обращения, комментарии, длинный текст |
| `ui` | 14 | 20 | 400 / 500 | 0 | Строки списка (заголовок — 500), кнопки, поля, меню |
| `meta` | 13 | 18 | 400 | 0 | Автор, отдел, категория в строке; таймлайн-события |
| `label` | 12 | 16 | 500 | 0.01em | Подписи в панели свойств, текст статус-пилла, заголовки колонок |
| `micro` | 11 | 14 | 500 | 0.02em | Счётчики в навигации, хоткеи. Минимум, ниже не опускаемся |
| `mono-id` | 12 | 16 | 500 | 0 | `PLS-1042` (mono) |
| `mono-num` | 13 | 18 | 500 | 0 | Таймер SLA, даты в таблицах (mono, tabular) |
| `kpi` | 24 | 28 | 500 | -0.01em | Числа в аналитике (Onest + tabular-nums, не mono) |

Правила для русского языка:
- **Sentence case** везде: «Новые обращения», а не «Новые Обращения».
- НЕ используем CAPS с разрядкой для подписей: кириллические прописные тяжёлые и длинные.
- Неразрывный пробел между числом и единицей: `3 ч`, `12 обращений`.
- Даты: `14 ноя, 18:00` (текущий год), `14 ноя 2025` (прошлый год). Относительное время до 7 дней: `2 ч назад`, `вчера`.
- Разряды тысяч — узким неразрывным пробелом (`1 248`), дробная часть — через запятую.
- Ширина текстового блока описания и комментариев — не больше 680px (~75 знаков).
- Русский текст длиннее английского на 15–25%: колонкам задаём `min-width`, у заголовков в строке всегда стоит `text-overflow: ellipsis` с полным заголовком в `title`.

### 3.2. Отступы и размеры

Базовая единица — 4px. Шкала: `0, 2, 4, 6, 8, 12, 16, 20, 24, 32, 40, 56, 72`.

| Элемент | Значение |
|---|---|
| Высота строки очереди | 36px (плотный режим — 32px) |
| Пункт сайдбара | 28px, горизонтальный паддинг 8px |
| Контролы | sm 28px / md 32px (по умолчанию) / lg 36px |
| Поля ввода | 32px; на мобильных шрифт ≥ 16px (Vercel guidelines) |
| Сайдбар | 232px, свёрнутый — 52px |
| Правая панель свойств | 288px |
| Основная колонка детальной страницы | max 720px, паддинг 32px по бокам |
| Шапка страницы | 48px |
| Шаг сетки свойств (label → value) | 2 колонки: 96px подпись + значение, вертикальный шаг 8px |

Внутренний ритм: 4–8 внутри компонента, 12–16 между связанными элементами, 24–32 между секциями. Отступы меньше 4 используем только для оптических поправок.

### 3.3. Радиусы: намеренно разные

Один радиус везде — признак шаблона. Радиус у нас кодирует **тип объекта**:

| Радиус | Объекты | Почему |
|---|---|---|
| **0** | Строки списка, ячейки таблиц, сайдбар, шапка, разделение «колонка ↔ панель» | Это «лист бумаги», разлинованный волосяными линиями, а не стопка карточек |
| **3px** | `kbd`-хоткеи, чекбоксы, ID-чипы, ячейки heatmap | Мелкие «технические» элементы, почти квадратные, как маркировка |
| **6px** | Кнопки, поля, селекты, пункты меню, hover-подсветка строки внутри меню, метки категорий | Интерактивные контролы |
| **10px** | Поповеры, дропдауны, тултипы с контентом, тосты, ИИ-блок | Плавающие слои |
| **14px** | Диалоги, командное меню `⌘K` | Самые крупные слои |
| **9999 (pill)** | **Только** статус-пиллы, аватары, точка непрочитанного | Круглое означает «состояние или человек». Квадратное означает «объект или категория» |

Правило вложенности: внешний радиус = внутренний + паддинг. Пример: поповер 10px с паддингом 4px содержит пункты меню 6px.

### 3.4. Слои, границы и тени

Основа плоская. Иерархию создают фон и одна волосяная линия, а не тени.

| Уровень | Светлая тема | Тёмная тема |
|---|---|---|
| 0 — фон приложения и сайдбар | `--bg` | `--bg` |
| 1 — рабочая область (список, детальная страница) | `--surface` + `1px --border` по одному ребру | `--surface` + `1px --border` |
| 2 — поповер, меню, тост | `--raised` + `1px --border` + `--shadow-pop` | `--raised` + `1px --border-strong`, без тени; сверху `inset 0 1px 0 rgba(255,255,255,.04)` |
| 3 — диалог, `⌘K` | `--raised` + `--shadow-dialog` + оверлей `rgba(28,27,24,.32)` | `--raised` + `1px --border-strong` + оверлей `rgba(0,0,0,.6)` |

```css
--shadow-pop:    0 1px 2px rgba(28,27,24,.06), 0 6px 16px -4px rgba(28,27,24,.12);
--shadow-dialog: 0 2px 4px rgba(28,27,24,.06), 0 16px 40px -8px rgba(28,27,24,.22);
```
- Каждая граница рисуется **один раз** (Geist). Строки списка отделяются `border-bottom` у строки, а не обводкой контейнера плюс строки.
- Карточка в карточке запрещена.
- Тени у строк и карточек в покое запрещены.

### 3.7. Графики (аналитика)
- Основной ряд рисуем чернилами (`--text-primary` с прозрачностью 0.85), сравнение — `--text-tertiary`. Акцент в графиках не используем.
- Heatmap «отдел × категория»: односторонняя тёплая шкала из 5 ступеней поверх `--surface`: `#F6F4EF → #EFE3D3 → #E6C9A8 → #D9A374 → #C27A45`. Число в каждой ячейке набрано mono-num. Цвет сравниваем с ячейкой, а не с текстом: текст всегда `--text-primary`, контраст на самой тёмной ступени 5.05:1 (проверено).
- Отделы с выборкой меньше 5 обращений (порог, как в R11) приглушены, у них метка «мало данных».
- Повторяющиеся проблемы показываем списком кластеров со sparkline за 8 недель, а не облаком тегов.

```css
--dur-instant: 70ms;   /* hover, pressed, чекбокс */
--dur-fast:    110ms;  /* фейды, тултипы */
--dur-base:    150ms;  /* поповеры, раскрытие секции, смена статуса в пилле */
--dur-slow:    240ms;  /* дроуэр/peek-панель, тосты */
--ease-standard: cubic-bezier(0.2, 0, 0.38, 0.9);
--ease-enter:    cubic-bezier(0, 0, 0.38, 0.9);
--ease-exit:     cubic-bezier(0.2, 0, 1, 0.9);
```

**Где моушн разрешён:**
- Цвет фона и рамки на hover и pressed.
- Появление поповера: opacity 0→1 и `translateY(4px)`→0.
- Тост: opacity и сдвиг 8px.
- Раскрытие секции правой панели.
- Пилл при смене статуса: crossfade 150ms.
- Новая запись в таймлайне: подсветка фоном `--accent-soft`, затухающая за 1.2s, один раз.

**Где моушн запрещён:**
- Командное меню `⌘K` и контекстные меню открываются мгновенно (R14).
- Навигация по списку стрелками и `J`/`K`.
- Переходы между страницами.
- Анимированные счётчики-«барабаны» и анимация чисел KPI.
- Тикающие секунды SLA: таймер обновляется раз в минуту без анимации.
- Bounce и spring на частых действиях.
- Скелетоны-«шиммеры» дольше 300ms: если данные пришли быстрее, скелетон вообще не показываем.

Анимируем только `transform`/`opacity`/`background-color`/`border-color`. `transition: all` запрещён. При `prefers-reduced-motion: reduce` все длительности становятся 0, кроме fade 110ms.

### 3.10. Статус-пилл
- Высота 20px, паддинг `0 8px 0 6px`, радиус 9999, gap 4px.
- Иконка 12px + текст `label` (12/16, 500), фон `tint`, цвет `fg`. Рамки в обычной теме нет; в high-contrast режиме — `1px fg`.
- В плотной строке очереди показываем **только иконку** 14px `fg` с тултипом «В работе — исполнитель занимается решением». Колонку статуса дублирует группировка или фильтр.
- В детальной странице, на главной и в карточках показываем полный пилл. В правой панели пилл одновременно служит триггером дропдауна смены статуса: chevron появляется на hover.
- Иконки статусов — собственный набор (круг 12px, stroke 1.5): пусто / ¼ / ? / ½ / ✓ / ⊘ / серый ✓. Форма различима и в ч/б.

### 3.11. Строка очереди (анатомия, 36px)

```
│●│▮▮▮│PLS-1042│◔│Не работает турникет на проходной корп. Б   [Пропуск/СКУД]  Склад · Анонимно │ ⏱ 3 ч 15 мин │ (ИП) │ 2 ч │
 6  16    72    14   flex 1, ui 14/500, ellipsis               метка категории  meta 13 secondary    88, mono-num   20    48
```
1. **Непрочитанное** — точка 6px `--accent` в левом гаттере 12px. У непрочитанного заголовок 600, у прочитанного 500.
2. **Приоритет** — иконка столбиков 16px.
3. **ID** — mono-id, `--text-tertiary`, фиксированная ширина 72px, выравнивание влево.
4. **Статус** — иконка 14px (см. 3.10).
5. **Заголовок** — `ui` 14/20 500, `--text-primary`, обрезка многоточием.
6. **Метка категории** — радиус 6px, высота 20px, `1px --border` + текст `meta` `--text-secondary`, без цветной заливки. Не больше одной метки, остальные показываются как «+2».
7. **Источник** — отдел · автор или «Анонимно» (иконка маски), `meta` `--text-secondary`.
8. **SLA** — правая колонка 88px, выравнивание вправо, mono-num (см. 3.12).
9. **Исполнитель** — аватар 20px. Если исполнителя нет, показываем пунктирный круг с tooltip «Не назначено».
10. **Обновлено** — `micro`/`meta` `--text-tertiary`, относительное время.

Поведение строки:
- Hover: фон `--subtle`, справа появляются быстрые действия («Назначить», «Статус»), которые перекрывают колонку «обновлено».
- Чекбокс появляется на hover на месте точки непрочитанного. При мультивыборе в низу экрана появляется панель массовых действий.
- Клавиатура: `J`/`K` или стрелки, `Enter` — открыть, `X` — выбрать, `1`/`2`/`3` — решения.
- Группировка по умолчанию — по SLA-риску: «Просрочено», «Истекает сегодня», «В срок», «На паузе». Заголовок группы 32px, `title-md` 15/600 + счётчик mono `--text-tertiary`, липкий при прокрутке.

### 3.12. Таймер SLA
- Формат — оставшееся время, две старшие единицы: `2 д 4 ч`, `3 ч 15 мин`, `45 мин`. Просрочка: `−1 д 2 ч`, где минус — U+2212, а не дефис. Между числом и единицей неразрывный пробел.
- Шрифт mono-num (13/18, 500, tabular). Колонка выровнена вправо, поэтому цифры стоят ровным столбцом.
- Пороги по умолчанию (настраиваются админом на категорию):
  - «под угрозой» — когда осталось меньше 25% срока или меньше 24 ч, что наступит раньше (по аналогии с Linear High risk, R4);
  - «просрочено» — после дедлайна.
- Визуальные состояния — по таблице в 3.5. Только «просрочено» получает тонированный фон-пилл: так красное пятно в очереди остаётся редким и значимым.
- На паузе: пока статус «Ожидает уточнения», часы стоят. Показываем `⏸ пауза` и в tooltip «SLA остановлен 12 ноя в 14:20, ждём ответа автора».
- В tooltip всегда абсолютный дедлайн: «Срок: 14 ноя, 18:00 (МСК) · назначен Ивановой А.».
- В правой панели под таймером тонкая полоска 2px «израсходовано срока», цвет по состоянию.
- В заголовке вкладки — число просроченных обращений (R6).

### 3.13. ИИ-подсказки: ИИ против локального fallback
Место — сразу под заголовком обращения, над описанием (R3). Блок свёрнут в одну строку, если подсказка одна.

```
┌ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ┐  ← 1px dashed --border-strong, радиус 10px, фон --surface
  [ИИ]  Подсказка · уверенность: высокая            Почему?
  Категория  → Пропуск/СКУД      Исполнитель → Отдел безопасности
  Похоже на: PLS-0987 «Турникет не считывает карту» (открыто)
                             [Принять  ⏎]  [Изменить]  [Отклонить]
└ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ┘
```
- **Источник всегда подписан** бейджем радиусом 3px в mono `micro` 11px:
  - `ИИ` — ответ модели;
  - `ПРАВИЛО` — локальный fallback: правила маршрутизации или ключевые слова из админки.
  
  Бейджи монохромные (`--subtle` + `--text-secondary`), отличаются текстом и иконкой (искра-контур против «шестерёнки-правила»).
- Пунктирная рамка означает «предложение, ещё не применено». После принятия блок исчезает, значения появляются в правой панели как обычные свойства. В таймлайне появляется condensed-событие «Категория “Пропуск/СКУД” — по подсказке ИИ · принял(а) А. Иванова» (Footprints, R13).
- **Fallback** показывается честно, строкой-caveat над блоком: «ИИ-сервис недоступен — предложение сформировано правилом “Слова: турникет, пропуск → СКУД”». Текст `meta`, `--text-tertiary`, иконка info. Блок выглядит так же, но бейдж `ПРАВИЛО`, а вместо «Почему?» — «Открыть правило».
- **Уверенность** показываем словами («высокая / средняя / низкая»), а не процентами. При «низкой» подсказка свёрнута по умолчанию.
- «Почему?» раскрывает 1–3 строки обоснования: совпавшие слова подсвечены `--accent-soft`, похожие обращения даны ссылками.
- Чего нет в ИИ-блоке: автоприменения без пометки, отдельного «ИИ-цвета» (фиолетовые градиенты), эмодзи ✨, анимации «печатающегося» текста для коротких полей.
- ИИ-сводка в аналитике запускается явной кнопкой «Сформировать сводку» (как «Analyze feedback» в R11). У сводки есть метка `ИИ`, время генерации и ссылки на обращения-основания.

### 3.14. Пустые состояния
Пустое состояние — текст и действие, без иллюстраций-маскотов. Структура: заголовок `title-md` + одна строка `body` `--text-secondary` + максимум одна кнопка + подсказка-хоткей. Выравнивание по левому краю колонки, отступ 72px сверху. По центру экрана не ставим.

| Ситуация | Текст | Действие |
|---|---|---|
| Очередь разобрана | «Очередь пуста. Последнее обращение обработано 14 мин назад.» | «Показать закрытые» |
| Пусто из-за фильтра | «По фильтру “Просрочено · Склад” ничего нет.» | «Сбросить фильтр» |
| Первый запуск (админ) | «Категорий пока нет. Без них обращения не будут распределяться автоматически.» | «Создать категорию» · `C` |
| Сотрудник ещё ничего не отправлял | «Здесь появятся ваши обращения и ответы на них.» | «Сообщить о проблеме» (основная кнопка) |
| Ошибка загрузки | «Не удалось загрузить очередь. Данные на экране — на 12:40.» | «Повторить» |

Правило «No dead ends» (R6): на любом пустом или ошибочном экране есть следующий шаг.

### 3.15. Детальная страница обращения
- **Шапка 48px:** хлебные крошки «Очередь / PLS-1042» (mono-id), стрелки «пред./след.» (`K`/`J`), «Копировать ссылку».
- **Основная колонка (≤720px):**
  1. Заголовок `title-xl`.
  2. Строка мета: автор или «Анонимно», отдел, «создано 12 ноя, 09:14».
  3. ИИ-блок.
  4. Описание `body`.
  5. Вложения: сетка превью 64px, радиус 6px.
  6. Таймлайн.
- **Таймлайн:**
  - События (смена статуса, назначение, срок, ИИ-применение) — condensed в одну строку `meta` `--text-secondary` с иконкой 14px на вертикальной линии `--border`.
  - Комментарии — полноформатные: аватар 24px, имя 14/500, время `--text-tertiary`, тело `body`.
  - **Решение** — отдельный тип записи с фоном `--subtle` и рамкой слева 2px цвета статуса, с заголовком «Решение: Отклонено» и обязательным обоснованием.
  - Внутренние комментарии (не видны автору) — фон `--subtle` + иконка замка + подпись «Видно только руководителям». Акцентный цвет здесь не используем: он зарезервирован за действиями пользователя.
  - Редактор комментария прилипает к низу колонки. Переключатель «Ответ автору / Внутренний» стоит слева от кнопки «Отправить».
- **Правая панель (288px):** секции «Решение» (кнопки действий с хоткеями), «Свойства» (статус, приоритет, категория, отдел, исполнитель, срок SLA), «Связанные», «Подписчики». Каждая секция сворачивается. Пары label/value — 96px + значение, клик по значению открывает дропдаун на месте.

### 3.16. Главная руководителя (action-first)
Сверху вниз:
1. Строка-приветствие без карточек: «Вторник, 10 ноября · у вас 3 просроченных и 5 истекают сегодня» (`title-lg` + `meta`).
2. **«Требует внимания»** — списки в формате строки очереди, сгруппированные по SLA-риску. В каждой группе не больше 5 строк и ссылка «все 12 →».
3. **«Новые без исполнителя»** — строки с инлайн-кнопкой «Назначить».
4. **«Повторяющиеся проблемы»** — 3–5 кластеров. Каждый — одна строка: название, число за 30 дней, sparkline 8 недель, дельта к прошлому периоду (текстом: «+4 к прошлому месяцу»).
5. Внизу справа тихая строка-сводка: «Среднее время решения 3,2 д · в срок 87%» (`meta`, mono-num). Без карточек и без «больших цифр».

| 8 | Пончики и круговые диаграммы для 2–3 значений, графики «для красоты» | Таблицы, heatmap со значениями в ячейках, sparklines. У каждого графика есть вопрос-заголовок («Где растут жалобы на СКУД?»). |

| 12 | Анимированные счётчики, шиммер-скелетоны на всё, bounce | Моушн только productive, ≤240ms, без анимации чисел (§3.9). |

| 18 | Фейковые «AI insights» без источников | Любая ИИ-сводка ссылается на обращения-основания и показывает время генерации. |

## 5. Краткая выжимка для реализации

- **Шрифты:** Onest 400/500/600 (+ `tnum` для чисел), JetBrains Mono 500 для ID, SLA и хоткеев.
- **Шкала:** 28/36 · 22/30 · 18/26 · 15/22 · 14/22 (body) · 14/20 (ui) · 13/18 · 12/16 · 11/14.
- **Отступы:** 4-кратные, строка 36px, контролы 28/32/36, сайдбар 232, панель 288, текст ≤720.
- **Радиусы:** 0 (листы и строки) · 3 (kbd, ID) · 6 (контролы) · 10 (поповеры) · 14 (диалоги) · pill (только статус и люди).
- **Светлая тема:** bg `#F6F4EF`, surface `#FCFBF8`, raised `#FFFFFF`, subtle `#EDEAE3`, border `#E2DED5`, border-strong `#CFCAC0`, text `#1C1B18` / `#57534B` / `#6B675F`, accent `#FF6B12` (hover `#F25C00`, текст на нём `#1C1B18`), accent-text `#B4480C`, accent-soft `#FFEEE2`, focus `#D2560B`.
- **Тёмная тема:** bg `#131210`, surface `#1A1916`, raised `#22211D`, subtle `#2A2824`, border `#33312C`, text `#EDEBE6` / `#B9B5AC` / `#96928A`, accent `#FF7A21`, accent-text `#FF9A52`, accent-soft `#3A2312`.
