# PULSE — защита и демонстрация

## Подготовка

Подробный пошаговый чек-лист — в [DEMO_CHECKLIST.md](DEMO_CHECKLIST.md). Коротко:

```bash
npm run db:seed
```

```bash
npm run dev
```

1. `db:seed` пересоздаёт демо-данные. Даты строятся от текущего момента, поэтому просрочки будут «свежими».
2. Если есть ключ Anthropic, проверьте, что он вставлен в `.env.local`. В настройках администратора на вкладке «AI» должно стоять «Ключ: настроен». Без ключа демонстрация тоже работает: подсказки будут с бейджем «ПРАВИЛО». Скажите об этом прямо — это и есть демонстрация fallback.
3. Откройте две вкладки: в обычном и в приватном окне. В одной будет сотрудник, в другой руководитель. Или переключайтесь через «Выйти / сменить роль».
4. Масштаб браузера 110–125%, светлая тема.

Не видно статус — в закупках, бухгалтерии и продажах. Неактуальные версии документов — в проектировании и проектном офисе. Сегодня такие сигналы живут в чатах: у них нет владельца, срока и итога. ## Сценарий живой демонстрации

| # | Роль | Действие | Что сказать |
|---|---|---|---|
| 1 | — | Страница входа | «Четыре роли. Входим как сотрудник закупок» |
| 2 | Сотрудник | «Мои обращения» → A-004 «Реализовано» | «Автор видит итог: что сделано, кем и когда. Это мотивирует писать дальше» |
| 3 | Сотрудник | «Новое обращение» → Проблема: «Не видно, на каком этапе согласование документов», 2–3 предложения → «Далее» | «Один вызов Claude Haiku: тип, категория, приоритет, похожие. Бейдж показывает источник — ИИ или правило» |
| 4 | Сотрудник | Блок «Похоже, об этом уже сообщали» → A-005 → «Поддержать» | «Вместо дубля — поддержка. Руководитель видит масштаб проблемы» |
| 5 | Сотрудник | «Кто рассмотрит» → включить «Скрыть моё имя» → «Отправить» | «Маршрут виден до отправки. Сразу назначены ответственный и срок реакции» |
| 6 | Руководитель | «Пульс» | «Сначала то, что требует действий: 4 просрочки, новые без реакции, ожидающие автора. Внизу повторяющиеся темы и нагрузка ответственных» |
| 7 | Руководитель | Открыть новое обращение | «Автор скрыт. Разбираем с AI: резюме, следующий шаг, проверка категории, готовый вопрос автору» → «Запросить уточнение» |
| 8 | Сотрудник | Карточка → «Ответственный задал вопрос» → ответить | «Ответ возвращает обращение на рассмотрение и уведомляет ответственного» |
| 9 | Руководитель | То же обращение → «Отклонить с объяснением» с коротким текстом. Пример готового отказа — A-017 | «Отказ без обоснования система не пропустит» → ввести полноценный текст, например «Решается в рамках A-005» |
| 10 | Руководитель | «Аналитика» → «Сформировать сводку» | «Claude Sonnet по всем обращениям: системные проблемы со ссылками на обращения и рекомендации. Метрики — из базы, у каждой есть определение» |
| 11 | Админ | «Настройки» → «Пользователи» → выключить «На месте» у Натальи Егоровой → «Категории» | «Отпуск — и новые обращения по каталогу автоматически уходят резервному. Ни одно не теряется» |

Запасной вариант без сети: шаги 3, 7 и 10 работают на локальных алгоритмах с бейджем «ПРАВИЛО».

## Конкурентные преимущества

1. Гарантия ответа: владелец, срок, эскалация, обязательный итог.
2. Борьба с дублями на входе и измерение масштаба через поддержку.
3. Полезный и экономный AI: один дешёвый вызов на подачу, по кнопке для разбора и сводки, кэш, бюджет, честный fallback.
4. Цепочка маршрутизации с резервными ответственными.
5. Скрытие имени без потери диалога с автором.
6. Доска результатов показывает, что голос сотрудника работает.

## Бизнес-ценность

- **Меньше потерь:** каждое обращение с владельцем и сроком. Просрочки видны руководителю в первой строке.
- **Меньше ручной работы:** не нужно искать адресата, разбирать и пересылать — категорию и маршрут определяет система. Разбор длинного обращения сокращается до резюме.
- **Системные решения вместо точечных:** темы и сводка показывают, где одно решение закроет несколько обращений. Например, «прозрачность статусов» — A-002, A-005, A-011.
- **Сохранённая память организации:** решения и мотивированные отказы не теряются в чатах.
- **Вовлечённость:** сотрудники видят результат.

Как измерять — KPI в [PRODUCT.md](PRODUCT.md#11-как-измерить-пользу-kpi). Достигнутые результаты не заявляем: их покажет пилот.

## Вероятные вопросы жюри

**Чем это лучше задачи в Битрикс24?**
Задача в Б24 — инструмент исполнения, когда уже известно, кто и что делает. PULSE закрывает этап до этого: приём, маршрутизацию по правилам, отсеивание дублей, обязательный итог автору и аналитику повторяющихся проблем. Интеграцию предлагаем так: решение «в работу» создаёт задачу в Б24.

**Что будет без интернета или без ключа AI?**
Всё продолжает работать. Категория подбирается по словарю ключевых слов, похожие ищутся по TF-IDF, темы — по доменному словарю. Интерфейс подписывает источник «ПРАВИЛО» и объясняет причину.

**Не уйдут ли конфиденциальные данные во внешнюю модель?**
Передаются только тексты обращений, без имён и контактов. Email и телефоны маскируются, у анонимных авторов не передаётся подразделение. AI можно выключить одной кнопкой или переменной окружения. Если политика ИБ запрещает внешние модели, архитектура позволяет подключить локальную модель: весь вызов изолирован в одном модуле.

**Сколько стоит AI?**
Подача — один вызов Haiku 5.5, доли цента. Сводка Sonnet 5.5 — несколько центов. Стоимость считается по фактическим токенам и видна администратору. Дневной бюджет ограничивает расходы жёстко.

**Анонимность настоящая?**
Это псевдонимность: имя скрыто от всех обработчиков, включая руководителя подразделения, но система хранит связь, чтобы автор получал ответы и уточнения. Мы прямо это пишем. Строгая анонимность — отдельный контур в плане развития.

**Как не завалить ответственных?**
Нагрузка видна руководителю, есть резервные ответственные, переназначение в один клик. Дубли превращаются в поддержку существующего обращения, а не в новые.

**Почему такие статусы?**
Это статусы из датасета: Новое, На рассмотрении, Ожидает уточнения, В работе, Реализовано, Отклонено, Закрыто. Плюс строгие переходы: из «Нового» нельзя сразу «Реализовано», финальные статусы требуют текста.

**Что из показанного — имитация?**
Ничего из показанного не имитируется: данные, права, маршрутизация, сроки и метрики работают на базе. Интеграции с Б24 и 1С не реализованы, они в плане развития. Демо-данные синтетические, из датасета организаторов.

**Как это масштабировать?**
Одно приложение плюс PostgreSQL выдерживают годовой поток обращений крупной группы. Узкие места и шаги описаны в [ARCHITECTURE.md](ARCHITECTURE.md#7-масштабирование).
