# PULSE — чек-лист демонстрации жюри

Сценарий выступления и ответы на вопросы — в [DEMO.md](DEMO.md). Здесь — что сделать руками и в каком порядке.

## За день до защиты

- [ ] Ключ Anthropic в `.env.local` (`ANTHROPIC_API_KEY="sk-ant-…"`); `AI_ENABLED="true"`; `DEMO_MODE="true"`.
- [ ] Прогнать проверки (≈4 минуты). Они работают на тестовой БД и демо-данные не трогают:
  ```bash
  npm run typecheck && npm run lint && npm test && npm run test:integration && npm run test:e2e
  ```
- [ ] Отрепетировать сценарий из DEMO.md хотя бы раз целиком, с таймером.

## За 15 минут до выступления

1. [ ] Остановить dev-сервер, если он запущен (Ctrl+C в его терминале).
2. [ ] Освежить демо-данные: сроки и просрочки считаются от текущего момента.
   ```bash
   npm run db:seed
   ```
   Это пересоздаёт демо-базу. Всё, что вы создавали на ней при репетиции, удалится.
3. [ ] Запустить сервер:
   ```bash
   npm run dev
   ```
4. [ ] Открыть http://localhost:3000. Если сессия осталась со вчера, PULSE просто покажет страницу входа — это нормально.
5. [ ] Войти администратором → «Настройки» → «AI»: «Ключ: настроен», «AI включён», расход за сегодня близок к нулю.
6. [ ] Прогреть экраны, чтобы dev-сервер скомпилировал их заранее: открыть по очереди «Пульс», «Все обращения», «Аналитика», карточку A-003, «Новое обращение». Первое открытие в dev-режиме занимает 1–2 с, повторные — мгновенные.
7. [ ] Сформировать сводку для руководства заранее (руководитель → «Аналитика» → «Сформировать сводку», ~15 с). На защите её можно обновить вживую или показать готовую.
8. [ ] Браузер: масштаб 110–125%, светлая тема, закрыть лишние вкладки. Сотрудника открыть в обычном окне, руководителя — в приватном.
9. [ ] Проверить интернет: AI-шаги требуют сети. Без сети они работают на локальных алгоритмах с бейджем «ПРАВИЛО» — скажите об этом жюри как о демонстрации fallback.

## Во время демонстрации

| Шаг | Роль | Что показать | Ожидаемый результат |
|---|---|---|---|
| 1 | — | Страница входа | Четыре роли, вход в один клик |
| 2 | Сотрудник | «Мои обращения» → A-004 | Итог «Реализовано» с текстом решения |
| 3 | Сотрудник | «Новое обращение»: «Не видно, на каком этапе согласование документов» + 2 предложения → «Далее» | Через 2–5 с: бейдж «ИИ», категория «Документооборот», похожее A-005 «Та же тема» |
| 4 | Сотрудник | «Поддержать» у A-005, включить «Скрыть моё имя», «Отправить» | Код A-021, ответственный Татьяна Морозова |
| 5 | Руководитель | «Пульс» | Просроченные сверху, повторяющиеся темы, нагрузка |
| 6 | Руководитель | Карточка нового обращения → «Разобрать» | «Автор скрыт»; резюме, следующий шаг, вопрос автору |
| 7 | Руководитель | «Запросить уточнение» из разбора | Обращение в статусе «Ожидает уточнения» |
| 8 | Сотрудник | Колокольчик → ответить на вопрос | Обращение вернулось «На рассмотрение» |
| 9 | Руководитель | «Отклонить» с коротким текстом, затем с полным | Короткий текст не принимается, полный — да |
| 10 | Руководитель | «Аналитика» → сводка | Системные проблемы со ссылками на обращения |
| 11 | Администратор | «Пользователи» → выключить «На месте» у Натальи Егоровой | Новые обращения по каталогу уходят резервному (Павел Громов) |

## Если что-то пошло не так

| Симптом | Действие |
|---|---|
| Страница бесконечно перезагружается | Сборка и dev-сервер работали одновременно. Остановить dev, затем `rm -rf .next`, затем `npm run dev` |
| Ошибки 500 сразу после обновления кода или миграции | Перезапустить dev-сервер: он держит старый Prisma Client в памяти |
| AI отвечает «ПРАВИЛО» вместо «ИИ» | Ничего не чинить на сцене: это работающий fallback, причина видна в подсказке у бейджа. После выступления проверить ключ, сеть и бюджет в «Настройки → AI» |
| «Слишком много неудачных попыток» | Использовать кнопки быстрого входа или подождать 5 минут |
| Пустой экран | Обновить страницу; данные подгружаются заново |

## После выступления

- [ ] Выключить быстрый демо-вход, если стенд остаётся доступным другим: `DEMO_MODE="false"`.
- [ ] Не публиковать `.env.local`: в нём ключ и секрет сессий.
